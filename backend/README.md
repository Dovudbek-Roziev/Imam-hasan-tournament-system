# API турнира «Имам Хасан»

Node.js / Express / MongoDB. Реализованы конфигурация, авторизация, русские ошибки, валидация моделей, атомарный пересчёт статистики, списки с фильтрами и пагинацией, dashboard и экспорт истории. Контракт результатов описан в [правилах турнира](docs/TOURNAMENT_RULES.md), маршруты, демоданные и экспорт — в [руководстве API](docs/API_GUIDE.md).

## Локальный запуск

Нужен Node.js 20.19+ и MongoDB replica set либо Atlas. Сервер проверяет поддержку транзакций до открытия HTTP-порта. Standalone MongoDB не подходит: результат и статистика сохраняются вместе. Тесты запускают собственный временный replica set.

Для локальной БД сначала настройте replica set; параметр `?replicaSet=rs0` в URI сам его не создаёт. Можно использовать строку подключения Atlas. Ограничение транзакций описано в [документации MongoDB](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/).

```powershell
cd backend
npm ci
npm run env:init
```

Команда env:init создаёт .env из примера, если файла ещё нет, и генерирует случайный JWT_SECRET. Существующий непустой секрет и остальные параметры сохраняются. Значение секрета не выводится в терминал.

Настройте MONGO_URI в backend/.env, затем выполните:

```powershell
npm run admin:create
npm run dev
```

admin:create создаёт пользователя в базе, указанной в MONGO_URI. Команда запросит имя, почту и пароль с повторным вводом. Пароль скрыт и должен содержать минимум 12 символов, максимум 72 байта UTF-8. Для автоматизации можно передать ADMIN_NAME, ADMIN_EMAIL и ADMIN_PASSWORD через секреты окружения. Общего пароля по умолчанию нет, публичной регистрации администратора нет.

## Переменные окружения

| Имя | Назначение |
| --- | --- |
| NODE_ENV | development, test или production |
| PORT | Порт HTTP, по умолчанию 5000 |
| TOURNAMENT_TIME_ZONE | IANA-пояс новых матчей; по умолчанию Asia/Bishkek, Ош, Кыргызстан |
| MONGO_URI | Строка подключения к MongoDB; только на сервере |
| JWT_SECRET | Случайный секрет, минимум 32 байта; генерируется env:init |
| JWT_TTL_SECONDS | Срок токена: 60–86400 секунд, по умолчанию 3600 |
| ALLOWED_ORIGINS | Точные адреса веб-админки через запятую, без завершающего слеша и пути |
| TRUST_PROXY | Число доверенных прокси, по умолчанию 0; для Render Blueprint используется 1 |

Для production ALLOWED_ORIGINS обязателен и принимает HTTPS-адреса. CORS не заменяет JWT-проверку. Мобильные запросы без Origin разрешены, но защищённые операции всё равно требуют токен. .env исключён корневым .gitignore.

## Аутентификация

| Метод и маршрут | Доступ | Результат |
| --- | --- | --- |
| POST /api/auth/login | Публичный, ограничен по частоте | JWT и безопасный профиль |
| GET /api/auth/me | Bearer JWT | Текущий профиль |
| POST /api/auth/logout | Bearer JWT | Отзыв всех токенов пользователя |

Пример тела входа:

```json
{
  "email": "admin@example.com",
  "password": "ваш-личный-пароль"
}
```

Успешный ответ содержит data.token, data.expiresIn и data.user. Передавайте токен в заголовке Authorization: Bearer TOKEN. JWT ограничен HS256, издателем, аудиторией и сроком действия. Каждый защищённый запрос дополнительно проверяет активность пользователя, актуальную роль и tokenVersion в MongoDB.

Роль «Администратор» разрешает запись; «Наблюдатель» её запрещает. create-admin создаёт администратора. Публичного управления ролями пока нет. Выход увеличивает tokenVersion, поэтому завершает все сеансы этой учётной записи. Смена JWT_SECRET завершает все сеансы всех пользователей. Автоматического продления токенов пока нет: после истечения нужен повторный вход.

## Турнирные маршруты

| Ресурс | Публичное чтение | Запись администратора |
| --- | --- | --- |
| /api/teams | GET /, GET /:id | POST /, PUT /:id, DELETE /:id |
| /api/players | GET /, GET /:id | POST /, PUT /:id, DELETE /:id |
| /api/matches | GET /, GET /:id | POST /, PUT /:id, DELETE /:id |
| /api/news | GET /, GET /:id | POST /, PUT /:id, DELETE /:id |
| /api/stats | GET /table, /top-scorers, /top-assists | Нет |

Дополнительно: `GET /api/stats/dashboard` и `GET /api/stats/archive` доступны только администратору. `GET /api/openapi.json` отдаёт публичную спецификацию. Списки команд, игроков, матчей и новостей ограничены 20 записями по умолчанию и возвращают `pagination`; клиент должен запрашивать следующие страницы. Фильтры, форматы и примеры описаны в [руководстве](docs/API_GUIDE.md).

## Ошибки и эксплуатация

Ошибки API возвращают success: false, стабильный технический code, русское message и requestId. Ошибки полей могут дополнительно содержать errors. Технические имена полей и коды остаются частью машинного API-контракта, а отображаемые сообщения написаны на русском.

HTTP: 400 — неверные данные, 401 — нет действительного сеанса, 403 — недостаточно прав/неразрешённый origin, 404 — не найдено, 409 — дубликат, устаревшая версия или конфликт с историей, 413 — слишком большой запрос, 429 — лимит запросов, 500 — внутренняя ошибка, 503 — недоступность БД/транзакций. Внутренние исключения и реквизиты подключения не возвращаются клиенту.

GET /health проверяет работоспособность HTTP-процесса. GET /ready возвращает 200 при подключённой MongoDB и 503 при её недоступности. HTTP начинает слушать только после подключения к БД. SIGTERM/SIGINT закрывают HTTP и MongoDB; максимальное ожидание — 10 секунд.

Лимит входа: 5 неудачных попыток с IP за 15 минут. Общий лимит API: 120 запросов с IP в минуту. Счётчики пока находятся в памяти одного процесса и сбрасываются при перезапуске. Для нескольких инстансов понадобится общее хранилище лимитов. При размещении за прокси нужно правильно настроить TRUST_PROXY, чтобы лимит применялся к клиентам, а не ко всему серверу.

## Проверки

Для существующей базы предусмотрен `npm run stats:rebuild`: команда пересчитывает производные показатели из завершённых матчей в одной транзакции. Она использует MONGO_URI из .env и изменяет статистику этой базы. Правила проверки старых протоколов и ограничения описаны в [документации](docs/TOURNAMENT_RULES.md). На пользовательской внешней базе команда в ходе разработки не запускалась.

```powershell
npm run check
npm run lint
npm test
```

Интеграционные тесты используют реальные HTTP-запросы и отдельный replica set mongodb-memory-server, не загружают рабочий .env. При первой установке/запуске тестов может понадобиться скачивание MongoDB binary. Временная БД удаляется после тестов.

Результат третьего этапа: 56/56 тестов прошли; lint без предупреждений, синтаксис 53 JavaScript-файлов проверен. Новые проверки охватывают фильтры и страницы, границы дат, время Оша, dashboard, экспорт истории, демоданные и OpenAPI. Сохранены проверки очков, голов, ассистов, автоголов, карточек, смены статуса/команд, удаления событий и матчей, защиты истории, входных полей, повторного пересчёта, старых английских значений, конкурентных изменений и отката после искусственной ошибки записи статистики.

Проверяются хеширование, вход, неправильные/истёкшие токены, блокировка пользователя, роли, защита всех 12 CRUD-операций записи, публичное чтение, реальные изменения команд, отзыв токенов, русские ошибки, CORS, лимиты, конфигурация и запуск/остановка сервера.

Для production устанавливайте зависимости через npm ci --omit=dev. Ранее обнаруженный advisory цепочки nodemon относится к dev-инструментам; он не исправлялся откатом на старую major-версию. Рабочие версии фиксируются package-lock.json.
